### 新增经验（已写进 docs/06 #21、#22 与 docs/10）

- **「旧闻的新编译」陷阱**：RSS 的 `pubDate` 是译文发布时间，不是事件时间。

  核验后实际发布于 9 月 3 日 —— 差点以当日头条入选。
  → 规则写死：**进 picks 前必须至少一次 WebSearch 核验真实发布日期**。
- **`topic` 不在 `focus` 内时配色静默回落**（不报错，只有不阻断警告）。
  → 明确定调：分类准确性优先于配色，不许为了配色把条目塞进「AI Coding」。

## 2026-09-14 · v0.5.0 · PPT 视觉层：渐变底 + 图标 + 原生图表

> 诉求原话：「ppt 没有图片」「背景色跟网页一样（多色混色渐变淡色）」「要有图标」
> 「数据分析」「各个模型的趋势」。

### 新增

- **`scripts/lib/png.mjs`** —— 只用 `node:zlib` 的极简 PNG 编码器 + 多色柔和渐变生成器。
  pptxgenjs 3.12 **不支持渐变填充**，所以「网页那种极光渐变」只能自己出图铺底。
  6 个变体（封面 / 内容 / AI Coding / 具身智能 / 数据 / 趋势），逐页按页型上底色。
- **`scripts/analyze.mjs` + `config/models.json`** —— 纯统计产出 `charts` 并写回 brief.json：
  置信度分布、分类分布、信源贡献、主体提及热度（含按 model/agent/robot 分组）、逐日趋势。
- **两页新图表**：「数据分析」（环形置信度 + 分类条形 + 信源条形）与
  「模型热度与趋势」（提及 Top8 条形 + 具身智能主体 + 10 天折线）。
- **18 个形状自绘图标**（不依赖图标字体/外部图片），用于页眉、统计卡、模块标题。

### 纪律没破（有断言守着）

- 背景**仍然属于浅色**：生成器断言「最暗通道 ≥ 228」，不达标 exit 1。
  实测 12 页导出图，背景最暗 229–245。
- 色相**先朝白色冲淡再叠加** —— 直接混饱和色相会把背景压暗（实测最暗落到 206，违规）。
- 斜线一律正规化成「非负宽高 + flipH/flipV」：pptxgenjs 传负 w/h 会写出
  `<a:ext cx="-914400">`（违反 OOXML），PowerPoint 可能弹「内容有问题，需要修复」。
- 渲染器**仍然只渲染**：图表数据来自 `brief.charts`，缺了就跳过两页并告警，绝不自己算。

### 验证

- `test-render`：17 passed / 0 failed（新增：页数公式 picks+7、背景图 == 页数、
  图表 == 6 个、无非法负 cx/cy、缺 charts 时降级为 picks+5 且不阻断）
- 渲染 12 页 798KB；COM 导出 12 张 1920×1080 PNG 逐页核对：6 种背景签名按页型
  正确分组、图表配色像素大量命中、无空白页
- `validate-brief` 新增 charts 一致性校验（confidence 与 picks 数量不符 → 报错）

### 更正

- **`docs/06 #16` 的判断被推翻**：PowerPoint COM 导出**不是不可用**，
  改用 Python `subprocess` 直调 powershell.exe（`-STA`）后稳定可用。
  当年的 E_FAIL 来自 Node spawn 的管道/时序，不是 COM 环境本身。

## 2026-09-14 · v0.4.0 · 手动触发（不再只靠定时）

> 需求原话：「增加一个可以主动生成的按钮，不止局限于定时生成」，
> 并把它嵌进 `aihub/landing/briefing.html` 的「生成 PPT」区块。

### 新增

- **`scripts/serve.mjs`** —— 手动触发生成服务。零第三方依赖（只用 `node:http`），
  把「抓取 → 选稿 → 渲染 → 打包」暴露成 7 个 HTTP 接口，带四步进度、单并发队列、
  `--selftest` 冒烟模式。**只监听 `127.0.0.1`**，无鉴权，不绑 `0.0.0.0`。
- **`scripts/draft-brief.mjs`** —— 机器草稿选稿。没有 Agent 的 `brief.json` 时，
  把「机器能自己确定的那部分」写合法：跨源聚簇、数独立信源、按规则定级、
  原文直出不改写。**不写点评、不给 A 级、不查重、不给冲突结论**。
- **`docs/09-手动触发生成服务.md`** —— 接口契约、两种模式对照、产物路径、
  安全边界、接前端的三种传参方式、8 条排错。
- `npm run serve` / `npm run draft`。

### 变更

- **`build-pptx.mjs` 支持降级标记**：选稿带 `draft:true` 时，封面加徽标、
  **每一页**页脚加「机器草稿」，输出文件名加 `_机器草稿` 后缀。
  逐页标记是刻意的 —— PPTX 会被单独截图传播，只标封面的话中间任意一页截出来就认不出。
- **草稿与正式产物永不同名**：否则一次「随手生成草稿」会静默覆盖 Agent 的正式 PPTX。

### 修复（都是真 bug，不是重构）

- **中文文件名导致下载 100% 失败**：`Content-Disposition: filename="AI日报.md"` 会让
  Node 抛 `ERR_INVALID_CHAR: Invalid character in header content`；而原先的 catch
  把异常静默吞掉，客户端只看到「下载失败」、服务端零日志。现按 RFC 6266 改为
  ASCII 兜底名 + `filename*=UTF-8''<百分号编码>`，并给 catch 加了落痕。
- **进度里显示的条数是错的**：`/(\d+)\s*条/` 匹配到第一条**逐源**日志，
  界面显示的是某个单源的条数（实测把 208 显示成 21）而不是总数。改为只认
  `[aggregate] 完成：N 条（去重后）`。
- **选稿步骤永远停在「running」**：草稿分支忘了把 step 状态置为 `done`。
- **草稿把同一件事选了两遍**：「Sam Altman 谈 OpenAI 不上市」被 Verge 与 TechCrunch
  各写一条，两条都进了正条目。根因是「信源集合重叠即判同事件」——
  同两家媒体各写一篇毫不相关的稿子，信源集合 100% 相同。改为以**标题相似度**为主判据，
  阈值 0.42 由实测标定（同事件 0.768/0.560，不同事件 0.158/0.188/0.000）。
- **草稿把数个来源并成一个 URL**：多源条目的各来源链接并未保存，
  原先把它们都指向本条 URL，等于伪造了「N 个来源可点」。现在只列真实存在的那一个链接，
  其余来源以名字形式写进「差异与冲突」并说明未保存独立链接。

### 前端（`aihub/landing`）

- `briefing.html` 新增 `#generate` 生成控制台：日期下拉、选稿方式、跳过抓取、
  立即生成按钮、四步进度、结果卡（含下载 PPTX / Markdown 与本期条目清单）。
- `assets/js/generate.js`（新）+ `components.css` 第 27 节（`.genx-*`）。
- 文案同步：hero「无需手动触发」→「也可随时手动触发一次」、能力卡、生成链路第 01 步。
- **不画假进度条**：服务没起来就直说没起来并给出启动命令。

### 验证

- `--selftest`：agent 模式（208 条 → 10 页）与 draft 模式（10 页，带草稿标记）均 exit 0
- 7 个接口逐个实测：健康/历史/选稿/建作业/轮询/下载 ×3/404/非法 JSON/CORS 预检
- 下载产物校验 `PK\x03\x04` magic + 字节数与磁盘一致；草稿 PPTX 10 页**页页**带标记，正式版 0 处标记
- 无头 Chrome 走真实浏览器点按钮跑通全链路（`?autogen=1`）：状态 →「完成（Agent 选稿）」、
  四步全绿、结果卡与下载链接齐备
- 布局实测 1280 / 900 / 375 三个宽度：无横向溢出、窄屏控件铺满、`--reduced-motion` 停止动效
- `test-render`：**11 passed, 0 failed**（build-pptx 改动后回归）
