# 09 · 手动触发生成服务（serve.mjs）

> 目标：**不只在 07:00 有早报，想现在要的时候也能现在就要。**
> 这条服务把「抓取 → 选稿 → 渲染 → 打包」暴露成 HTTP 接口，
> 任何前端（落地页、仪表盘、curl）点一下就能触发一次**真实**生成。

---

## 一、为什么要有它

定时（cron）只解决「到点了自动跑」，解决不了这四种情况：

1. 想看今天现在什么情况，不想等明天早上。
2. 开会前临时要一版，手上没有。
3. 改了 `config/sources.json` 或渲染脚本，想立刻验证效果。
4. 落地页/看板上要有个按钮，让人**当场**看到这东西能跑，而不是只看截图。

前三种是自己用，第四种是给别人看。两种都需要「一键、真实、有进度」。

---

## 二、快速开始

```bash
cd ai-news-kit
npm run serve                 # 等价于 node scripts/serve.mjs
# [serve] ai-news-kit v0.4.0 · http://127.0.0.1:8787
```

浏览器打开 <http://127.0.0.1:8787> 是一个自检页（今日状态 + 各接口链接）。

触发一次生成：

```bash
# POST 后拿到 jobId，然后轮询
curl -s -X POST http://127.0.0.1:8787/api/generate \
     -H 'Content-Type: application/json' \
     -d '{"date":"2026-09-14","mode":"auto","noFetch":true}'
# {"ok":true,"jobId":"2026-09-14-003","reused":false}

curl -s http://127.0.0.1:8787/api/jobs/2026-09-14-003
```

不想起服务、只想验证整条链路能跑通：

```bash
node scripts/serve.mjs --selftest --date 2026-09-14
node scripts/serve.mjs --selftest --mode draft          # 强制走机器草稿
```

`--selftest` 跑完打印 JSON 结果（含四步耗时与产物路径）后退出，退出码 0/1 ——
CI 或改完代码后的冒烟都用它。

## 三、接口契约

所有接口都返回 JSON（下载接口除外），并带 `Access-Control-Allow-Origin: *`
（落地页可能是 `file://` 或另一个端口，不给 CORS 就连不上）。

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/health` | 服务版本、Node 版本、今天日期、`busy/queued`、今日 `hasNews/hasBrief/hasPptx/hasDraftPptx` |
| GET | `/api/history` | 最近 60 天，每天是否有 `news / brief / draft / pptx`，以及产物大小与 mtime |
| GET | `/api/brief?date=` | 当期选稿摘要（`focus / headline / stats / picks[no,topic,title,lv,srcCount]`），供前端展示「生成了哪几条」 |
| POST | `/api/generate` | 建作业，返回 `{jobId}`；`202` 新建，`200` 表示复用了同一天正在跑的任务 |
| GET | `/api/jobs/:id` | 作业状态：`status / phase / steps[] / result / error / warnings` |
| GET | `/api/download?date=&kind=pptx\|md&draft=0\|1` | 取产物文件（带 RFC 6266 文件名） |
| GET | `/` | 人肉自检页 |

`POST /api/generate` 的请求体：

```jsonc
{
  "date":    "2026-09-14",   // 省略 = 今天（**本地时区**，不是 UTC）
  "mode":    "auto",         // auto | agent | draft
  "noFetch": false,          // true = 复用已有 news.json，跳过抓取
  "force":   false           // true = 同一天已有任务在跑时也新建一个
}
```

作业状态机的 `steps` 固定四项，顺序即真实执行顺序：

| key | label | 做什么 |
|---|---|---|
| `fetch` | 抓取信源 | `aggregate.mjs`（`noFetch` 时为 `skip`） |
| `select` | 选稿 | 有 Agent 的 `brief.json` 就走 `validate-brief.mjs`；没有就 `draft-brief.mjs` |
| `analyze` | 统计图表数据 | `analyze.mjs`：纯统计并把 `charts` 写回 brief.json。失败只标 warn，PPT 少两页图表页 |
| `render` | 渲染 PPTX | `build-pptx.mjs`（内置溢出校验，失败不写文件） |
| `pack` | 生成 Markdown | `brief-to-md.mjs`（失败只标 `warn`，不作废整批） |

`status` 取值：`queued` → `running` → `done` / `error`。单步还有 `skip`（跳过抓取）与 `warn`（失败但不阻断）。
单并发 + 队列 —— 两个任务并行渲染会互相覆盖文件。

## 四、两种选稿模式（这是本服务最要紧的设计）

| | `agent` | `draft`（机器草稿） |
|---|---|---|
| 触发条件 | `data/<date>/brief.json` 存在 | 上者不存在，或显式 `mode=draft` |
| 内容来源 | Agent 写的选稿 | `draft-brief.mjs` 按规则直出 |
| 点评 `why` | 有 | **空着**，只陈述事实边界 |
| 置信度上限 | A | **B**（A 需要核验一手官方材料，机器做不到） |
| 历史查重 | 有 | 无 |
| 跨源数字比对（定 D 级） | 有 | 无 |
| PPT 标记 | 无 | 封面徽标 + **每一页**页脚「机器草稿」 |
| 文件名 | `AI日报_<date>.pptx` | `AI日报_<date>_机器草稿.pptx` |

三处刻意的设计，别当成没写完：

1. **`auto` 优先用 Agent 的稿**。机器草稿是兜底，不是默认质量线。
2. **草稿的评级上限是 B**。A 级要求「可追溯到一手官方材料」，那要打开原始页面核验 ——
   机器做不到就不给，宁可整体偏低。
3. **草稿单独命名 + 逐页标记**。否则一次「随手生成草稿」会静默覆盖掉 Agent 的正式产物，
   而且从文件名上完全看不出来；PPTX 会被单独截图传播，只标封面的话，中间任意一页截出来就认不出是草稿了。

> 与项目纪律一致：**降级产物必须显式标注，绝不静默产出、绝不让人误把草稿当正式日报。**

草稿的聚簇规则（标题级近似匹配）是本服务里唯一带调参的部分，阈值有实测依据：

| 关系 | 标题字符 bigram Jaccard |
|---|---|
| 同一事件（Verge vs TechCrunch 报道同一件事） | 0.768 / 0.560 |
| 不同事件 | 0.158 / 0.188 / 0.000 |

所以阈值取 **0.42**；另有一条辅助判据（至少两家共同信源 + 标题相似度 ≥0.25 + 三天内），
用来捞「同一事件但标题写法差很远」的情况。
⚠ 不要退回「信源集合重叠就判同事件」的写法 —— 同两家媒体各写一篇毫不相关的稿子，
信源集合 100% 相同，那样会把两周前的旧闻并进今天的事件里（已经踩过，见 `docs/06`）。

## 五、产物路径

| 模式 | PPTX | Markdown |
|---|---|---|
| agent | `<产物根>/AI日报_<date>/AI日报_<date>.pptx` | `<产物根>/AI新闻推送_<date>.md` |
| draft | `<产物根>/AI日报_<date>/AI日报_<date>_机器草稿.pptx` | `<产物根>/AI新闻推送_<date>_机器草稿.md` |

产物根默认是 `ai-news-kit/../`（即仓库根），可用 `--out` 改：

```bash
node scripts/serve.mjs --out D:/dist --port 9000
```

这样与手工跑 `npm run pptx` 的默认输出位置一致 —— 手动生成的产物不会跑到另一个平行目录里去。

## 六、安全边界（务必读完再改）

- **只监听 `127.0.0.1`**。这不是公网服务，在没有鉴权的前提下**绝不**监听 `0.0.0.0`，
  也不要套公网反代。要暴露给局域网，请先自己加一层 token。
- 服务会**在本机执行子进程并写文件**，等于把「跑流水线」的能力开放给了任何能访问该端口的人。
- 下载接口按 `date + kind` 拼路径，只接受 `YYYY-MM-DD` 形状的日期并固定落在产物根下，
  不要给它加「任意路径」参数。
- 前端默认指向 `http://127.0.0.1:8787`，可用 `?api=` 覆盖。跨站调用靠 CORS `*` 放行，
  这是本地工具，不引入凭据。

## 七、接到落地页

`aihub/landing/briefing.html` 的「生成 PPT」区块内嵌了控制台（`#generate`），
逻辑在 `landing/assets/js/generate.js`，样式在 `components.css` 第 27 节。

对接方式（就近优先）：

```
?api=http://127.0.0.1:9000   >   window.AIHUB_GEN_API   >   元素 data-gen-api   >   localStorage   >   默认 127.0.0.1:8787
```

两个给自动化用的深链参数（也方便「从别处一键生成」）：

| 参数 | 作用 |
|---|---|
| `?autogen=1` | 打开即生成一次（不用手点，验证脚本因此能跑通整条链路） |
| `&nofetch=1` | 配合 `autogen` 使用：跳过抓取，复用已有数据 |

页面**不画假进度条**。服务没起来就直说「没起来」，并把启动命令给出来 ——
这个项目所有的卖点都是「这条消息能不能信」，界面自己更不能演。

## 八、排错

| 现象 | 原因与处理 |
|---|---|
| `EADDRINUSE` | 端口被占。换端口：`--port 8788`，并用 `?api=http://127.0.0.1:8788` 打开落地页 |
| 页面显示「生成服务未启动」，但服务明明在跑 | **系统代理**。本机若设了 `HTTP_PROXY` 且 `NO_PROXY` 为空，请求会被送到代理（实测 `fetch` 直接 `terminated`）。把 `127.0.0.1` 加进代理绕过列表。注意 Node 的 `fetch`(undici) 会读环境变量，而 `node:http` 不会 —— **自检脚本请用 `node:http`** |
| 下载总是失败 | 文件名是中文时，`Content-Disposition` 里直接写 `filename="AI日报.md"` 会让 Node 抛 `ERR_INVALID_CHAR`，表现为「下载失败」而服务端一行日志都没有。正确写法是 ASCII 兜底名 + `filename*=UTF-8''<百分号编码>`（本服务已按 RFC 6266 实现） |
| 抓取步骤报「去重后 N 条」但 N 很小 | 看 `--selftest` 输出里的 `源失败（阻断级）` 计数；服务会把它作为 warning 返回 |
| 界面只显示「抓到 21 条」这类奇怪数字 | 解析子进程输出时**别用 `/（\d+）条/` 这种宽泛正则**，它会匹配到第一条**逐源**日志。要认总结行 `[aggregate] 完成：N 条（去重后）` |
| 渲染报「溢出校验失败」 | 这是设计如此（fail-fast）。按提示精简 `brief.json` 的 `title/event/why/keyFacts`；草稿模式则检查 `draft-brief.mjs` 里的 `BUDGET` 上限 |

## 九、定时任务怎么配合

两者不是替代关系：

```bash
# 每天 08:00 抓数据（可以进 cron）
0 8 * * * node /abs/path/ai-news-kit/scripts/aggregate.mjs

# 渲染不要进 cron：它必须等 Agent 产出 brief.json 之后才跑
```

- **定时**负责「不漏」：每天固定时间抓 + 由 Agent 选稿产出 `brief.json`。
- **手动**负责「现在就要」：任何时刻点一下，走同一条链路；没有 Agent 的稿时降级为机器草稿，
  并在产物上明确标出来。

> 有了手动触发之后，一条实用的分工是：定时只跑到「抓取 + Agent 选稿」，
> 渲染与交付交给人和按钮决定 —— 反正渲染只要 0.3 秒。
