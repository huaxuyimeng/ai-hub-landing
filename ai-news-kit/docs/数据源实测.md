## 三、几个观察

### 1. `ai-bot` 是 HTML 解析，最脆弱

其他源都是 RSS/Atom/JSON，`ai-bot` 是抓 HTML 再用正则切。
它条数最多（40），但**页面一改版就挂**。

`config/sources.json` 里给它标了 `"fragile": true`。
如果哪天它返回 0 条，先别查网络，去看页面结构变了没有。

### 2. TechCrunch 既是好源也是陷阱

好：常出独家，是一手来源。
陷阱：**它是很多转载链的源头**。看到多家报道时，先确认它们是不是都在转 TC。

见 [03-置信度评级规则](./03-置信度评级规则.md) 的 Mecka 案例。

### 3. Hacker News 用 `points>50` 过滤

Algolia API 直接带 `numericFilters=points>50`，返回 30 条。
这个过滤是有意的——HN 上未过滤的 AI 条目噪声太大。

### 4. 中英文不平衡

中文 6 / 英文 4，且三家英文源（TC / MIT TR / Verge）里，
真正有独立深度采编的只有 MIT TR 一家。

缺口：**有独立采访能力的英文科技媒体**。
（→ 已列入 [07-演进路线](./07-演进路线.md) P2）

## 四、加新源的检查清单

- [ ] 先 `curl` 一次，确认返回的是 XML/JSON 而不是 HTML
- [ ] 确认返回条数 ≥10（少于 10 条不值得加）
- [ ] 确认 AI 浓度（随手看 5 条，≥3 条相关才加）
- [ ] 确认 `publishedAt` 能解析出来（解析不出的源价值大打折扣）
- [ ] 在 `aggregate.mjs` 里加 `parseXxx`（照抄现有的改，约 20 行）
- [ ] 跑一次 `aggregate.mjs`，看总数和 `sourceHealth`
- [ ] 更新本文件

## 五、源健康度判定

`aggregate.mjs` 会写 `sourceHealth`：

| 情况 | 动作 |
|---|---|
| 1–2 源失败 | 记健康度，日报标注「今日 X 源不可达」，继续 |
| **≥3 源失败** | **停止出日报，报故障** |

为什么是 3：10 个源挂 1–2 个，候选池仍够；
挂 3 个以上，**多源交叉验证的基础就塌了**——
此时出的日报看起来正常，实际上已失去可信度依据。这比不出更危险。
