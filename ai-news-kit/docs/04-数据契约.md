# 04 · 数据契约

> `brief.json` 是唯一真相源。这份文档定义它的每一个字段。
> 校验可用 `schema/brief.schema.json`。

---

## 一、`brief.json` 顶层结构

```jsonc
{
  "date": "2026-09-14",                    // 必填，YYYY-MM-DD，本地时区
  "windowNote": "…",                        // 抓取窗口说明（为什么是这批数据）
  "focus": ["AI Coding", "具身智能"],        // 侧重方向
  "headline": "…",                          // 今日一句话总览，3–4 句，要有观点
  "rawStats": { … },                        // 抓取统计，见下
  "confidenceScale": [ … ],                 // 置信度量表（会被渲染成 PPT 第 3 页）
  "picks": [ … ],                           // ★ 要闻，3–5 条
  "alsoWorthAScan": [ … ],                  // 扫读清单
  "dedupeNote": "…"                         // 查重说明（比对了哪几轮）
}
```

---

## 二、`rawStats` · 抓取统计

从 `aggregate.mjs` 的输出抄过来，**不要编**。

| 字段 | 类型 | 说明 |
|---|---|---|
| `sourcesAlive` | number | 存活信源数 |
| `sourcesTotal` | number | 配置的信源总数 |
| `rawItems` | number | 原始条目数 |
| `dedupedItems` | number | 去重后条数 |
| `multiSourceItems` | number | 多源共同报道条数 |
| `byCategory` | object | 分类分布，key 为中文分类名 |
| `crossSourceThreshold` | number | 多源关联阈值（当前 3） |
| `note` | string | 方法论说明 + 阈值依据 |

> ⚠️ 「AI Coding 88 条」这类分类数是**关键词粗匹配**的结果，含大量误召回。
> 写进统计是诚实的（数据确实如此），但要配 `note` 说明它不是筛选结果。

---

## 三、`confidenceScale` · 置信度量表

固定四项，顺序 A→D。会被渲染成 PPT 第 3 页。

```jsonc
[
  { "lv": "A", "name": "极高", "rule": "≥3 个独立信源，且可追溯到一手官方材料" },
  { "lv": "B", "name": "高",   "rule": "2 个独立信源，或 1 个信源 + 一手官方材料" },
  { "lv": "C", "name": "中",   "rule": "单一信源报道；含「多家转载同一家独家」" },
  { "lv": "D", "name": "存疑", "rule": "关键数字互相矛盾，或全部溯源到同一信源且无官方确认" }
]
```

## 四、`picks[]` · 要闻（核心）

```jsonc
{
  "no": 1,                        // 序号，从 1 开始
  "topic": "AI Coding",           // "AI Coding" | "具身智能"（决定 PPT 配色）
  "title": "…",                   // 一句话，尽量含关键数字
  "lv": "A",                      // A/B/C/D
  "publishedAt": "2026-09-10",    // ★ 真实发布时间，不是抓取时间
  "event": "…",                   // 3–5 句，只写事实，不写评价
  "keyFacts": ["…", "…"],         // 3–5 条，尽量带可验证数字
  "why": "…",                     // ★ 必须回答「所以呢」
  "sources": [                    // 每项 { name, url }，一手来源排第一
    { "name": "Anthropic 官方报告（一手）", "url": "https://…" }
  ],
  "conflicts": "…"                // 各源差异；一致就写「无实质冲突」
}
```

### 逐字段要求

| 字段 | 要求 | 常见错误 |
|---|---|---|
| `title` | 一句话说清，含关键数字 | 写成标题党，或漏掉主体 |
| `topic` | 只用两个值（决定配色） | 自己造新分类——PPT 会 fallback 到 AI Coding 色 |
| `lv` | 严格按 [03-置信度评级规则](./03-置信度评级规则.md) | 凭感觉、按转载数 |
| `publishedAt` | **真实发布时间** | ❌ 用抓取时间冒充 |
| `event` | 3–5 句，纯事实 | 混入评价（"这是重大突破"） |
| `keyFacts` | 3–5 条，带数字 | 全是空泛形容词 |
| `why` | **对读者决策的影响** | ❌ 复述事件 |
| `sources` | `name` + `url`，一手排第一 | 只写媒体名不写 URL |
| `conflicts` | 有差异必写 | 留空 |

### `why` 字段写法对照

| ❌ 反面 | ✅ 正面 |
|---|---|
| 「这标志着 AI Coding 能力的重大突破，值得业界高度关注。」 | 「Coding Agent 的典型负载是同一仓库前缀反复命中缓存，V4.1-Flash 把缓存占用砍到 1/4，等于把这条成本曲线整体下移一档。MIT 许可让有数据 residency 要求的团队可私有化部署——这是闭源旗舰给不了的。」 |
| 「显示了具身智能的巨大潜力。」 | 「扩场景 » 堆数据 > 堆参数。同样预算，多租几个真实场地扫场景比多训一倍时间有用得多（+16.7 vs +0.8）。另外跨本体零样本如果站得住，机器人公司不必为每个本体重训一套导航。」 |

共同点：**给出了读者下一步该做什么的暗示**（该重新算成本 / 该改预算分配 / 该进设计约束）。

## 五、`alsoWorthAScan[]` · 扫读清单

```jsonc
{ "title": "…", "sources": "量子位 / AITNT（2 源）" }
```

进这里的三种情况：

1. 信源不足（只有聚合站条目）
2. 与本期正条目主题重复
3. 上一轮已推送过，本期有新进展但不值得再占正条目

## 六、`news.json` 结构（抓取产物）

由 `aggregate.mjs` 生成，**不要手改**。

```jsonc
{
  "date": "2026-09-14",
  "generatedAt": "2026-09-14T00:06:38+08:00",
  "sourceHealth": { "aitntnews": { "ok": true, "count": 20 }, … },
  "items": [
    {
      "id": "hash…",
      "title": "…",
      "url": "https://…",
      "source": "aitntnews",
      "sourceLabel": "AI TNT News",
      "category": "AI Coding",
      "publishedAt": "2026-09-10T…",
      "summary": "…",
      "relatedSources": ["aitntnews", "hn"],   // 多源关联结果
      "relatedTokens": ["claude", "code", …]   // 共享实体 token
    }
  ]
}
```

关键字段：

- **`relatedSources`** —— 多源关联结果，长度 ≥2 表示多源共同报道。
  ⚠️ 这是**聚合层的代理指标**，不等于独立信源数。评级前必须人工核验。
- **`relatedTokens`** —— 命中的共享实体 token，用来判断关联是否合理。

## 六·补 · `charts`（图表数据，v0.5.0 起）

> **不要手写。** 跑 `node scripts/analyze.mjs --date <日期>` 由脚本统计后写回本文件。
> 渲染器只读它、绝不在这里算 —— 否则同一份 brief 换个渲染器就会得到不同图表。

| 字段 | 产出方 | 说明 |
|---|---|---|
| `corpus` | analyze | 语料元信息：条目数、起止日期、跨度、**口径说明** |
| `confidence` | analyze | 本期 A/B/C/D 数量。**必须与 picks 实际数量一致**，validate-brief 会比对，不一致直接报错 |
| `category` | analyze | 抓取语料的分类分布（`name` + `count`） |
| `sources` | analyze | 各信源贡献条数（`id` + `label` + `count`） |
| `models.top` | analyze | 主体提及热度总榜 |
| `models.topByKind` | analyze | 按 model / agent / robot 分组 —— 总榜会被大模型刷屏，具身智能公司需要独立一张 |
| `models.trend` | analyze | `days`/`dates`/`series[]`/`dailyTotals`/`windowDays`，逐日提及次数 |

模型与机器人关键词表在 `config/models.json`，改完重跑 analyze 即可。

## 七、校验

```bash
# JSON 合法性
node -e "JSON.parse(require('fs').readFileSync('data/2026-09-14/brief.json','utf8')); console.log('OK')"

# 字段完整性（简易自检）
node -e "
const b=JSON.parse(require('fs').readFileSync('data/2026-09-14/brief.json','utf8'));
const req=['date','headline','rawStats','confidenceScale','picks','alsoWorthAScan'];
console.log('缺失顶层字段:', req.filter(k=>!b[k]));
b.picks.forEach(p=>{
  const miss=['no','topic','title','lv','publishedAt','event','why','sources'].filter(k=>!p[k]);
  if(miss.length||!(p.keyFacts||[]).length) console.log('pick',p.no,'问题:',miss,'keyFacts:',(p.keyFacts||[]).length);
});
console.log('picks:',b.picks.length,'| 评级:',b.picks.map(p=>p.lv).join(''));
"
```
